# React — Wrapper Components

## 1. What is a wrapper component?

A wrapper component is a component that surrounds other content or components to provide a shared layout, styling, behavior, or functionality without needing to rewrite that logic for every child.

The key idea is that the wrapper handles something around the content, while the wrapped content remains responsible for its own purpose.

For example, imagine you have several sections in an application that need the same border, padding, and background. Instead of repeating those styles everywhere, you create a `Card` wrapper.

## 2. Basic implementation using `children`

```
type CardProps = {
  children: React.ReactNode;
};

function Card({ children }: CardProps) {
  return (
    <div className="card">
      {children}
    </div>
  );
}
```

Now use the wrapper with different content:

```
function App() {
  return (
    <>
      <Card>
        <h2>User Profile</h2>
        <p>Pranay's profile information</p>
      </Card>

      <Card>
        <h2>Settings</h2>
        <button>Save Changes</button>
      </Card>
    </>
  );
}
```

Both sections receive the same outer styling, but their inner content is different.

### How does the composition work?

App

Chooses the content

Card

Provides the wrapper

children

The JSX passed between the Card tags

The parent supplies JSX through the `children` prop. React renders that JSX wherever the wrapper places `{children}`.

Importantly, `children` is not a special rendering mechanism that automatically wraps content. It is a prop that React populates with the content nested inside a component's opening and closing tags.

## 3. Wrapper components can provide behavior too

Wrappers aren't limited to styling. They can also implement shared behavior such as event handling, loading states, error boundaries, or access checks.

For example, a wrapper that handles clicks:

```
type ClickWrapperProps = {
  children: React.ReactNode;
  onClick: () => void;
};

function ClickWrapper({
  children,
  onClick,
}: ClickWrapperProps) {
  return (
    <div onClick={onClick}>
      {children}
    </div>
  );
}
```

Usage:

```
<ClickWrapper onClick={() => console.log("Clicked")}>
  <button>Click me</button>
</ClickWrapper>
```

The wrapper provides the click handler around its children. Note that clicking the button can trigger both the button's own handler and the wrapper's handler through event bubbling.

In real applications, choose the appropriate HTML element for the wrapper. For example, use a `<button>` for a single button-like action rather than making an arbitrary `<div>` interactive when possible.

## 5. Wrapper components vs. props composition

These concepts overlap, but they emphasize different things.

| Concept           | Main idea                                                                                                               |
| ----------------- | ----------------------------------------------------------------------------------------------------------------------- |
| Wrapper component | A component surrounds other content or components.                                                                      |
| Props composition | A broader technique for building components by supplying content, elements, component types, or behavior through props. |
| `children`        | The conventional prop for content nested between component tags.                                                        |

For example, a wrapper using `children`:

```
<Card>
  <UserProfile />
</Card>
```

A component using named content props:

```
<PageLayout
  header={<Header />}
  sidebar={<Sidebar />}
  content={<UserProfile />}
/>
```

Both use composition. The first is a straightforward wrapper; the second explicitly defines several content slots.

## 6. Wrapper components vs. higher-order components (HOCs)

A higher-order component is a function that takes a component and returns an enhanced component.

```
function withBorder<P extends object>(
  Component: React.ComponentType<P>
) {
  return function WithBorder(props: P) {
    return (
      <div className="border">
        <Component {...props} />
      </div>
    );
  };
}
```

Usage:

```
const BorderedProfile = withBorder(UserProfile);

<BorderedProfile />;
```

Compare the two approaches:

- Wrapper component: You explicitly nest the component inside another component.
- HOC: You call a function that creates a new component with the enhancement applied.

Both can reuse behavior or presentation. A wrapper is a component-level composition pattern; an HOC is a component-enhancement pattern.

## 7. Common mistakes

- Forgetting to render `children`: The content passed by the parent won't appear unless the wrapper renders it.
- Overusing wrappers: Extra layers can make the component tree harder to understand without adding meaningful reuse.
- Using a wrapper when a simple element is enough: Not every `<div>` needs a component abstraction.
- Assuming wrappers automatically share state: Two instances of the same wrapper have separate state unless they explicitly use shared state, context, or another shared store.
- Confusing client-side access checks with security: Hiding a page in React doesn't secure its API or data.

## Interview revision

A wrapper component surrounds child content to provide reusable layout, styling, behavior, or context. It commonly accepts `children` as `React.ReactNode` and renders it inside a shared structure. Wrapper components are one practical application of React composition, whereas HOCs enhance components through a function that returns another component.

Mental model: The wrapper decides what surrounds the content; the parent decides what goes inside it.
