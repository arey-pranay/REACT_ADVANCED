# React Fundamentals: Props Composition

## 1. What is props composition?

Props composition is the practice of building flexible, reusable components by passing other components, JSX elements, functions, or configuration through props.

Instead of making a component responsible for every detail of its UI, you let the parent decide which pieces to provide and how they fit together.

The core idea is separating a component's structure and behavior from the specific content it displays.

For example, a reusable `Card` shouldn't need to know whether it contains a user profile, a product, or a notification. It can receive that content through props.

## 2. The simplest example

Suppose we have a generic `Card` component.

```
type CardProps = {
  title: string;
  children: React.ReactNode;
};

function Card({ title, children }: CardProps) {
  return (
    <section className="card">
      <h2>{title}</h2>
      <div>{children}</div>
    </section>
  );
}
```

Now use it for different purposes:

```
function App() {
  return (
    <>
      <Card title="Profile">
        <p>Pranay Parikh</p>
        <button>View profile</button>
      </Card>

      <Card title="Notifications">
        <p>You have 3 unread messages.</p>
      </Card>
    </>
  );
}
```

Both instances share the same card structure, but their contents differ.

`Card` controls the outer layout. The parent controls what goes inside.

Parent: `App`

Chooses the content

Reusable `Card`

Profile content

Notification content

### What makes this composition?

The parent assembles the UI from smaller components. `Card` doesn't need separate implementations such as `ProfileCard`, `NotificationCard`, and `ProductCard` merely because their content differs.

You can reuse one component and compose different interfaces around it.

## 3. The different forms of props composition

### A. `children` composition

This is the most common form.

```
type PanelProps = {
  children: React.ReactNode;
};

function Panel({ children }: PanelProps) {
  return <div className="panel">{children}</div>;
}
```

Usage:

```
<Panel>
  <h2>Account settings</h2>
  <p>Update your preferences.</p>
</Panel>
```

Use `children` when the component provides a wrapper, layout, or visual container around arbitrary content.

Examples: cards, modals, panels, layouts, tabs, and page shells.

### B. Named component or element props

Sometimes a component needs multiple distinct content regions rather than one `children` area.

```
type PageLayoutProps = {
  header: React.ReactNode;
  sidebar: React.ReactNode;
  content: React.ReactNode;
};

function PageLayout({
  header,
  sidebar,
  content,
}: PageLayoutProps) {
  return (
    <div>
      <header>{header}</header>
      <div className="layout">
        <aside>{sidebar}</aside>
        <main>{content}</main>
      </div>
    </div>
  );
}
```

Usage:

```
<PageLayout
  header={<h1>Dashboard</h1>}
  sidebar={<nav>Navigation</nav>}
  content={<p>Dashboard content</p>}
/>
```

This is useful when the component has clearly defined slots.

Mental model: `children` is a general content slot; named props give specific regions their own slots.

### C. Component props

Instead of receiving an already-created element, a component can receive a component type.

```
type EmptyStateProps = {
  Icon: React.ComponentType<{ size?: number }>;
};

function EmptyState({ Icon }: EmptyStateProps) {
  return (
    <div>
      <Icon size={32} />
      <p>No results found.</p>
    </div>
  );
}
```

Usage:

```
function SearchIcon({ size = 24 }: { size?: number }) {
  return <span style={{ fontSize: size }}>⌕</span>;
}

<EmptyState Icon={SearchIcon} />;
```

Here, `EmptyState` receives a component and decides where to render it and which props to provide.

This is useful for configurable icons, input controls, renderers, and other pluggable UI elements.

Note the distinction:

- `icon={<SearchIcon />}` passes a React element.
- `Icon={SearchIcon}` passes a component type.

Use the first when the parent creates the element. Use the second when the receiving component needs to instantiate the component itself or control its props.

### D. Function props

A function prop can let the parent customize behavior or determine content based on data.

```
type User = {
  id: number;
  name: string;
};

type UserListProps = {
  users: User[];
  renderUser: (user: User) => React.ReactNode;
};

function UserList({ users, renderUser }: UserListProps) {
  return (
    <ul>
      {users.map((user) => (
        <li key={user.id}>{renderUser(user)}</li>
      ))}
    </ul>
  );
}
```

Usage:

```
<UserList
  users={[
    { id: 1, name: "Pranay" },
    { id: 2, name: "Alex" },
  ]}
  renderUser={(user) => <strong>{user.name}</strong>}
/>
```

This is closely related to the render props pattern you studied earlier. The parent provides a function, and the component invokes it to customize the rendered output.

Use function props when the component needs to provide data or events to the consumer's callback.

## 4. Why is props composition important?

Imagine building a modal.

A tightly coupled implementation might look like this:

```
function ProfileModal() {
  return (
    <div className="modal">
      <h2>Profile</h2>
      <p>Profile details go here.</p>
      <button>Close</button>
    </div>
  );
}
```

If you also need a settings modal, a confirmation modal, and a delete modal, you might duplicate the same structure.

Composition lets you extract the shared structure:

```
type ModalProps = {
  title: string;
  children: React.ReactNode;
  onClose: () => void;
};

function Modal({ title, children, onClose }: ModalProps) {
  return (
    <div className="modal">
      <h2>{title}</h2>
      <div>{children}</div>
      <button onClick={onClose}>Close</button>
    </div>
  );
}
```

Then compose different content:

```
<Modal title="Profile" onClose={closeModal}>
  <ProfileDetails />
</Modal>

<Modal title="Delete account" onClose={closeModal}>
  <p>Are you sure you want to delete your account?</p>
  <button onClick={deleteAccount}>Delete</button>
</Modal>
```

The modal owns the shared structure and close behavior. Its parent supplies the content and the specific deletion behavior.

This makes components easier to reuse, test, and change independently.

## 5. Props composition vs inheritance

React generally favors composition over inheritance for sharing UI structure and behavior.

| Inheritance-oriented approach                | Composition-oriented approach                         |
| -------------------------------------------- | ----------------------------------------------------- |
| A child class extends a base class           | A component receives props and renders other elements |
| Behavior may be inherited from a hierarchy   | Behavior and content are explicitly supplied          |
| Reuse depends on class relationships         | Reuse depends on combining independent pieces         |
| Can become tightly coupled to the base class | Components can be combined in different ways          |

React components don't need to inherit from a base UI class to reuse a layout. A `Modal` can wrap arbitrary content, and a `PageLayout` can accept any sidebar or header.

Composition doesn't mean inheritance is always wrong in programming. It means that for most React UI reuse, composing components tends to be more flexible and explicit.

## 6. Props composition vs other React patterns

These concepts overlap, but they solve slightly different problems.

| Pattern                      | Main purpose                                                                                   |
| ---------------------------- | ---------------------------------------------------------------------------------------------- |
| Props composition            | Customize a component by passing content, elements, components, or functions through props     |
| Render props                 | Use a function prop to determine what gets rendered                                            |
| Higher-order component (HOC) | Wrap a component to enhance it                                                                 |
| Custom hook                  | Reuse logic inside function components                                                         |
| Context                      | Make values available to descendants without passing them through every intermediate component |
| Compound components          | Build a coordinated component API from several related components                              |

For example, a modal can use props composition for its content, a custom hook for keyboard handling, and context for coordinating nested modal subcomponents. These approaches can complement each other.

## 7. Common mistakes

1\. Making components overly configurable. Don't add dozens of props for hypothetical future requirements. Add flexibility when a real use case benefits from it.

2\. Passing a component when an element is sufficient. If the consumer doesn't need to control how a component is instantiated, passing `<Icon />` may be simpler than passing `Icon`.

3\. Using `children` for every situation. If a component has distinct regions such as `header`, `sidebar`, and `footer`, named props may express the API more clearly.

4\. Confusing composition with shared state. Passing children or components doesn't automatically make their state shared. State ownership still depends on where that state is declared and how components communicate.

5\. Creating a generic abstraction too early. Two pieces of JSX that look similar don't always need a reusable component. Extract one when it gives you a useful, coherent interface.

## 8. Interview revision

- What is props composition? Building reusable UIs by passing content, elements, component types, functions, and configuration through props.
- Why use it? To separate shared structure from specific content and behavior.
- What is `children` composition? Passing nested JSX into a component through its `children` prop.
- When use named slots? When a component has distinct content regions.
- How does it relate to render props? Render props are a specialized form of composition that uses a function prop to customize rendering.
- How does it relate to custom hooks? Composition reuses and combines UI; custom hooks reuse logic.
- What is React's general preference for UI reuse? Composition rather than inheritance-based component hierarchies.

One-line mental model: props composition lets a component define where and how content fits, while the parent decides what content and behavior to supply.
